# Мини Фигма

Мини-редактор фигур в браузере на **React + TypeScript + Tailwind CSS v4** (сборка Vite).
Это один сайт из **двух страниц**: лендинг о проекте и сам рабочий редактор.

Живые версии:

- лендинг — https://limebrad.github.io/lifigma/
- редактор — https://limebrad.github.io/lifigma/editor.html

## Две страницы

| Страница | Вход | Что это |
| --- | --- | --- |
| Лендинг | `index.html` → `src/landing/main.tsx` → `src/landing/App.tsx` | рассказ о проекте: возможности, шаги, FAQ, призыв открыть редактор |
| Редактор | `editor.html` → `src/editor/main.tsx` → `src/editor/EditorApp.tsx` | рабочий холст: фигуры, слои, свойства, история |

Обе страницы собираются одной сборкой Vite: список входов задан в
`vite.config.ts` (`build.rollupOptions.input`). Ссылка с лендинга на редактор
строится от базового пути (`import.meta.env.BASE_URL`), поэтому работает и
локально, и в подпапке GitHub Pages.

## Структура

```
src/
├── index.css          # Tailwind + дизайн-токены обеих страниц
├── landing/           # лендинг: вход (main.tsx) и сборка секций (App.tsx)
├── editor/            # вход и каркас редактора (main.tsx, EditorApp.tsx)
├── types/             # единый язык проекта: фигуры, инструменты, контент лендинга
├── constants/         # контент и числа: инструменты, тексты лендинга, палитра, подписи
├── utils/             # чистая математика: экран <-> мир, хит-тесты, помощники DOM
├── hooks/             # логика без интерфейса: фигуры, камера, клавиши, появление блоков
└── components/
    ├── *.tsx          # редактор: Canvas, Shape, Toolbar, LayersPanel, PropertiesPanel
    ├── landing/       # секции лендинга: Hero, Features, Steps, Showcase, Audience, Faq …
    ├── ui/            # общее: Button, Container, Icon, IconBadge, Logo, Reveal, SectionHeading
    └── visuals/       # векторные иллюстрации (SVG)
```

Правила, которые держат код в единстве:

- `types/` — единственное место, где описаны сущности; остальные файлы импортируют оттуда.
- `constants/` — единственный источник правды о контенте и числах: инструменты и
  горячие клавиши (`tools.ts`), тексты и ссылки лендинга (`landing.ts`), палитра
  редактора (`colors.ts`), подписи фигур (`shapes.ts`).
- `hooks/` не знают про DOM, `components/` не знают, как хранится состояние: всё
  передаётся пропсами.
- Состояние фигур редактора пишется **только** через `commitShapes` в
  `useShapes`, иначе зеркало `shapesRef` разойдётся с отрисованным.
- Иллюстрации лендинга — собственные SVG (`components/visuals`) в той же палитре,
  что и редактор (`constants/colors.ts`).

## Лендинг

- секции по порядку: Hero, возможности, «как пользоваться», «как устроено»,
  «кому подойдёт», FAQ, финальный призыв и футер;
- весь текст и ссылки собраны в `src/constants/landing.ts`, разметка секций — в
  `src/components/landing`;
- блоки плавно появляются при прокрутке (`Reveal` + `IntersectionObserver`),
  визуал мягко «парит»;
- аккордеон FAQ доступен с клавиатуры и объявляет состояние через
  `aria-expanded`/`aria-controls`;
- единственная внешняя ссылка — официальный сайт Figma, и только чтобы честно
  пояснить, что проект с компанией Figma не связан.

## Редактор

- сетка на фоне холста (мелкая, крупная + мировые оси, линии сетки совпадают с миром 0);
- панорамирование: **пробел + левая кнопка** или средняя кнопка;
- зум колесом **от 10% до 400%** с привязкой к точке под курсором (нормирован под тачпад);
- инструменты в левой панели: выбор, прямоугольник, эллипс;
- рисование фигуры перетаскиванием мыши, `Escape` отменяет рисование;
- **выделение**: клик, `Shift`+клик (добавить), `Ctrl/Cmd`+клик (переключить), `Ctrl/Cmd+A` (всё);
- **перетаскивание** мышью — вся выборка едет как единое целое;
- **удаление** выделенного: `Delete` / `Backspace`;
- **история**: `Ctrl/Cmd+Z`, повтор — `Ctrl/Cmd+Shift+Z` или `Ctrl/Cmd+Y`;
  частые правки одного свойства сливаются в один шаг;
- **панель свойств**: тип, координаты, размер, цвет заливки (пикер, hex/CSS-ввод, палитра пресетов);
- **панель слоёв**: список фигур сверху вниз, клик по слою выделяет фигуру на холсте.

Полный разбор качества кода и список исправленных дефектов — в [AUDIT.md](AUDIT.md).

## Доступность

Холст помечен `role="application"` с подписью, смена выделения озвучивается
скринридером, инструменты — `radiogroup`, слои — `listbox` с множественным
выбором. На лендинге есть ссылка «Перейти к содержимому», у аккордеона FAQ —
`aria-expanded`/`aria-controls`, а анимации отключаются при
`prefers-reduced-motion`. Полноценного рисования с клавиатуры пока нет
(см. AUDIT.md, P2).

## Команды

```bash
npm install
npm run dev          # запуск обеих страниц
npm run build        # проверка типов + сборка в dist/
npm run typecheck    # только проверка типов
npm run lint         # eslint
npm run preview      # локальный просмотр собранного dist/
```

В обоих режимах действует базовый путь `/lifigma/`: Vite печатает точный адрес
в консоли, лендинг открывается по `/lifigma/`, редактор — по `/lifigma/editor.html`.

Требуется Node **>= 20.19** (или 22 LTS) — этого требует Vite 8.
В CI те же проверки выполняются перед публикацией: линт, затем сборка.

## Публикация

Каждый пуш в `main` запускает workflow «Deploy to GitHub Pages»
(`.github/workflows/deploy.yml`): `npm ci` → `npm run lint` → `npm run build` →
выкладка в GitHub Pages. Базовый путь сборки — `/lifigma/`, он задан в
`vite.config.ts` и соответствует адресу сайта.
