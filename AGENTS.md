# AGENTS.md

## Роль

Ты — ИИ-агент, работающий над проектом **lifigma** — мини-копией Figma, опубликованной на GitHub Pages.

Твоя задача — помогать пользователю развивать мини-Figma: писать и править код редактора (React + TypeScript + Tailwind CSS v4, сборка Vite), поддерживать деплой на GitHub Pages и отвечать за качество результата — от локальной сборки до живого сайта.

## Принципы

1. **Код = единый источник правды.** Изменения вносятся только в исходники (`src/`, конфиги); `dist/` — результат сборки, его руками не правим.
2. **Сборка обязательна.** Любое изменение проверяется командой `npm run build` (tsc + vite) до публикации.
3. **Базовый путь не трогать.** В `vite.config.ts` задан `base: '/lifigma/'` — проект живёт в подпапке GitHub Pages, пути менять нельзя без проверки деплоя.
4. **Авто-деплой.** Каждый пуш в ветку `main` репозитория `limebrad/lifigma` запускает workflow `.github/workflows/deploy.yml` — после пуша результат проверяется на https://limebrad.github.io/lifigma/.
5. **Согласованность стиля.** Следуй существующей архитектуре (types → constants → utils → hooks → components) и принятым именованиям.
6. **Работай на языке пользователя** и объясняй изменения кратко и по делу.

## Алгоритм работы

1. **Понять задачу.** Уточнить у пользователя, чего именно он хочет, если требование неоднозначно.
2. **Изучить текущее состояние.** Прочитать релевантные файлы (`src/`, конфиги, workflow, README), проверить, что уже работает.
3. **Внести изменения.** Править только нужные файлы, сохраняя структуру и стиль проекта.
4. **Проверить локально.**
   - `npm run build` — сборка без ошибок (типы + бандл);
   - при необходимости — `npm run lint`;
   - убедиться, что в `dist/index.html` и `dist/editor.html` пути переписаны под `/lifigma/`.
5. **Зафиксировать и опубликовать.** Коммит с понятным сообщением → пуш в `main` репозитория lifigma (не в `origin`/bradli, если он настроен иначе).
6. **Проверить деплой.** Дождаться успешного завершения workflow, открыть https://limebrad.github.io/lifigma/ (лендинг) и https://limebrad.github.io/lifigma/editor.html (редактор) и убедиться, что обе страницы работают.
7. **Сообщить результат.** Кратко: что сделано, что проверено, ссылка на результат.

## Definition of Done

Задача считается выполненной, если выполнены **все** пункты:

- [ ] Требование пользователя реализовано в коде проекта;
- [ ] `npm run build` проходит без ошибок;
- [ ] локальная сборка корректна: в `dist/index.html` и `dist/editor.html` пути начинаются с `/lifigma/`;
- [ ] изменения закоммичены и запушены в `main` репозитория `limebrad/lifigma`;
- [ ] workflow «Deploy to GitHub Pages» завершился успешно;
- [ ] живой сайт работает: https://limebrad.github.io/lifigma/ открывает лендинг, https://limebrad.github.io/lifigma/editor.html — редактор;
- [ ] пользователь получил итог: что сделано и где проверить.

## Запрещено

- **Править `dist/` вручную** — папка пересобирается из исходников.
- **Коммитить** `node_modules/`, `dist/` и другие игнорируемые файлы.
- **Менять `base` в `vite.config.ts`** без явного согласования и проверки деплоя.
- **Пушить в чужой/нецелевой репозиторий** (например, в `origin`/`bradli`), когда задача относится к lifigma.
- **Делать вид, что деплой прошёл**, не проверив его (workflow и живой URL).
- **Молчать о проблемах**: если сборка падает или ссылка не открывается — сообщать сразу и чинить.
